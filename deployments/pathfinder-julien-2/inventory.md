## Conflicts with the worktree's mechanisms

- **Consolidation merge (J8, J11 to J13 with `unfence`).** Both sides rewrote the same block of `run_thread`. The merged version must persist the raw reply (J11), then unfence and apply the LaTeX check before archiving and replacing the account; a non-LaTeX reply must BLOCK without archiving. The `run_thread` handler must catch `EvidenceUnavailable` alongside `(Stopped, Refused)`.
- **Admission and `Refused`.** `admission.Refused` raised inside `_stage_call` must still propagate as a stop; J9's retry loop, if it were upstreamed, would need to leave `Refused` alone. J9 as written turns a transport failure into BLOCKED, which bounded runs and `run_pair` then skip, while the worktree expects a resumable stop.
- **Monkeypatched transport.** `julien2/campaign.py research_run` and `eva2/campaign.py run` replace `transport.execute` with a bridge and call `research.run_thread` directly. This bypasses admission, active-call records, engine receipts, the stub backend and run records (`runner` is never entered). The bridge also rewrites identities to include round and repair (upstream identities repeat across rounds), rejects verdicts lacking `requires_new_research` and `feasible_within_remaining`, and returns an empty "not_admitted" reply when a peer round reservation is unavailable. Admission decisions are only admit, defer or stop, so that skip behaviour has no equivalent; the verdict guards have no extension point (`extensions.SUPPORTED` is `admission` and `snapshot_extra`).
- **Prompt copies.** julien-2 writes full copies of `peer.md`, `consolidate.md`, `verify.md` with its brief appended into each run's `prompts/`; eva2 does the same for every prompt. Under per-file resolution these become full replacements and silently keep pre-`947fdf4` text. They should become `R.append.md` overlays.
- **Pinning and freeze.** julien-2 pins by engine commits (`d274c1e`, `323bf39`) that are not in this repository, so `verify-frozen` cannot check its copies against the engine repository. The EVA end-to-end test points at the live sibling checkout instead of a pin.
- **Stub backend.** The stub consolidation reply writes nothing to peer directories and cites no paths, so J1 to J5 are not exercised by stub runs; a julien-2 contract fixture needs peer artefacts and ledger path references of its own.
- **Two archive rules.** J12 archives with exclusive create before every replacement; E4 archives only when content differs and overwrites. One rule should survive.
